# 30 — ext4/jbd2 文件系统实现计划（四阶段）

> 基线为 Linux 2.6.39.4 / x86_64。Core 只承诺 P1–P3 子集；完整基线特性、挂载语义
> 与 ABI 差距进入 M10 Parity，不得以核心子集宣称完整 ext4 parity。

> 目标：minios 读写 e2fsprogs 生成的 ext4 镜像，参照 Linux 2.6.39.4 fs/ext4 与
> jbd2 的模块边界；host `mke2fs/debugfs/dumpe2fs/e2fsck` 是外部验证工具。

## 0. 磁盘格式与统一接受规则

- Superblock：字节偏移 1024，magic 0xEF53；解析 blocks/inodes/free 计数、group
  geometry、inode/desc size、块大小及 `s_feature_{compat,ro_compat,incompat}`。
  64bit 时组描述符和块号高位必须完整解码，不能按 32 位截断。
- Inode：解析 i_mode、i_size_lo/i_size_hi、i_blocks_lo/高位、i_flags、i_block[15]、
  i_extra_isize 等。i_size_hi 与 i_blocks 高位来自相应 osd 字段，不按 x86_64
  指针宽度推断磁盘字段宽度。
- Extent：校验 header magic/entries/max/depth、索引与叶节点边界；深度和 entries
  上限按冻结的 Linux 2.6.39.4 源码/e2fsprogs 规范检查，不保留未经核实的固定深度数。
  `ee_start_hi` 是**物理块号高位**，与逻辑长度或 `i_size_hi` 无关。
- 目录：校验 dirent rec_len/name_len/file_type；htree 仅接受已实现的 hash 版本和
  合法 dx_root/dx_node 索引，损坏或未知格式返回错误，不得跳坏项继续当成功。
- jbd2：读取 journal superblock、sequence/start 与 descriptor/commit/abort/revoke；
  journal 自己的 feature 位也走白名单校验。

### 0.1 COMPAT / RO_COMPAT / INCOMPAT × RO/RW

挂载在任何数据读写前按下表和阶段白名单作统一判定；super、journal、inode 路径
共用同一结果，禁止一处校验、另一处静默忽略。

| 类别 | RO 挂载 | RW 挂载 |
|------|---------|---------|
| COMPAT | 仅接受审计后的只读安全白名单；逐位确认语义，不得一律忽略 | 仅接受写路径已完整维护语义的位；未知/未实现位拒绝 |
| RO_COMPAT | 仅接受审计后的 RO 安全白名单；未入白名单的未知位也拒绝 | 未知位一律禁止 RW；已知位只有在写路径能维护其不变量时接受 |
| INCOMPAT | 未知或未实现位一律拒绝 | 未知或未实现位一律拒绝，并需支持对应写语义 |

- **P1–P3 在 RO/RW 都统一拒绝 metadata_csum**；不得提前校验部分 checksum 后又称
  只读支持。P4 才实现完整校验与写回更新。
- `has_journal`（COMPAT）只表示日志存在，`needs_recovery`（INCOMPAT）表示必须回放，
  两者分开判定。M7 前凡有 recovery 需求，即使 RO 也拒绝；无 recovery 的
  has_journal 镜像可由 P1 只读。P3 才可 replay 后 RW。
- M6 RW 基线镜像必须 `^has_journal`。`noload` 只是挂载选项，不是 mke2fs feature，
  也不代表 replay；它不能把带恢复需求的镜像变成 M6 可写镜像。
- 所有拒绝均返回明确挂载/IO 错误且不得修改镜像，测试同时覆盖正例与拒绝例。

## 1. 阶段 P1 — 只读（M5）

范围：RO 挂载；1k/2k/4k 块；extent 读；线性/htree 目录；filetype、快/慢 symlink、
stat/lseek/getdents/readlink/statfs。P1 是 **extent-only**：普通文件或目录没有
EXTENTS_FL、仍使用直接/间接块映射时明确返回不支持，不得把 i_block 当作 extent 解析；
快速符号链接按独立内联格式处理。

- super.c：统一特性矩阵、geometry/组描述符校验与加载、挂载/卸载。
- inode.c：按 group/index 定位 inode，完整解码 64 位 i_size/i_blocks 与 extent 根；
  RO 路径不回写 atime。
- extents.c：按 depth 遍历索引并查找逻辑块；洞与 unwritten extent 读零，物理块号
  使用 u64 合成 `ee_start_hi:ee_start_lo`，所有乘法/加法检查溢出。
- namei.c/dir.c：线性扫描或经合法 htree 索引定位；索引不支持时只能在格式允许且
  不改变语义的情况下完整线性扫描，损坏索引不得被当成空目录。
- Gate：特性拒绝矩阵、extent/htree host 单测及 §5 黄金清单、内容与 e2fsck 闭环。

## 2. 阶段 P2 — 无日志读写（M6）

本阶段保持 xv6 root 和独立 ext4 第二盘布局不变，只对第二盘进行 RW；不得改写 xv6 root。

- alloc.c：组选择、位图分配/释放、inode 分配与统计回写；分配失败回滚本操作的
  所有内存/磁盘状态，配额不在 Core。
- extents.c：尾部合并、新 extent、索引插入与正确 split；深度增长按冻结源码/规范
  上限检查。未实现的 unwritten 转换/fallocate 必须报错且不得部分修改。
- dir.c：rec_len 收缩插入、块满分配、线性到 htree 的完整构建。已索引目录必须
  正确 split 并更新 dx 索引；或者完整重建为线性目录、清该 inode 的 INDEX_FL 与
  dx_root/dx_node 后再追加。**禁止保留 dx_root 却伪装成线性追加**；两种路径都未
  实现或失败时返回明确错误，操作不得留下半修改目录。
- inode.c/namei.c：truncate、link/unlink、rename、link/dtime 与时间戳维护；所有
  计数与位图保持一致。
- **M6 RW 仅接受 `^has_journal` 基线**，needs_recovery 一律拒绝；不得以 noload
  冒充无日志或回放。现有干净 journal 的镜像只走已支持的 RO 路径，P3 才接日志 RW。
- fsync：相关数据/元数据 BIO 完成后必须执行并成功返回真实 IDE CACHE FLUSH；
  flush 失败向上传播，普通写完成不能代替持久化确认。
- 大文件写：以 `i_size_lo + i_size_hi` 维护 64 位 i_size，以低位+高位维护
  i_blocks，并按 huge_file 语义处理块计数单位；同步校验 large_file/huge_file
  特性与计数溢出。64bit 组描述符支持不能替代这些 inode 字段。
- 内部物理块号保持 u64；若完整 >2^32 块设备分配/RW 留到 M10，P2 必须明确拒绝
  越界分配，不能截断写错块，但 extent 高位解码及独立测试仍须正确。

## 3. 阶段 P3 — jbd2 核心日志（M7）

- 事务：handle → transaction{tid,buffers,state}；descriptor/tag → 元数据日志块 →
  commit(seq) → checkpoint/环形复用；replay 处理 descriptor/commit/abort/revoke，
  revoke 必须阻止旧块引用被错误回放。
- 挂载先检查 journal superblock 的 COMPAT/RO_COMPAT/INCOMPAT。只接受已实现的
  最小特性集；不支持的 checksum（含 CSUM_V2/V3）、64bit、async commit 及未知位
  一律拒绝，不得忽略后继续挂载或 replay。
- has_journal 且 needs_recovery 时先在同镜像完成 replay，再允许 RW；无恢复需求也
  必须验证 journal feature/geometry，不能只信 inode 8 存在。
- 所有元数据修改由 journal handle 包裹。ordered 模式保证文件数据先于引用它的
  元数据提交持久化；提交前等待 ordered 数据和日志写并执行真实 CACHE FLUSH，
  commit 确认后再 flush，才允许 checkpoint/复用日志块。错误必须中止提交流程。
- fsync = 所需数据落盘 + 相关事务提交 + 设备 flush 全部成功。Core 只实现 ordered；
  writeback/data=journal 与完整 barrier/FUA 语义进入 Parity，不影响上述基础 flush gate。
- Gate：§5 的离线 e2fsck、内容/操作语义，以及 UP 参考配置中按预声明类别计数的
  200 次有效写中 crash 全部通过；M8 SMP 专项是追加证据，不能折抵这 200 轮。

## 4. 阶段 P4 — M10 Parity 与显式扩展

- M9 冻结的 **M10 Parity 项均必须完成，不允许豁免**：按基线清单关闭
  flex_bg/64bit 完整写、xattr、unwritten/fallocate、完整 jbd2 与挂载语义等差距。
- metadata_csum 仅在 P4 实现：RO 校验 super/GD/位图/inode/目录等全部约定元数据，
  RW 同步更新；未完整实现前仍按 P1–P3 规则拒绝，不能只校验组描述符即宣称支持。
- metadata_csum、inline_data、encryption、verity、casefold 等属于或包含后 2.6
  扩展，**不是 Parity-2.6.39.4 必备项**。只有显式立项并冻结扩展配置后才实现/验收；
  不得将其缺失记为 2.6.39.4 parity 失败，也不得让其挤占已冻结 M10 项。
- bigalloc、project quota、mmp 及其他扩展同样逐位按 §0.1 拒绝或立项，不默认接受。

## 5. 测试闭环（与 40-testing-ci.md 联动）

1. **镜像生成不是黑盒**：现代 mke2fs 每条用例显式 `-O` 指定/关闭特性（P1–P3
   包含 `^metadata_csum`，M6 RW 包含 `^has_journal`）；随后用 `dumpe2fs -h` 核对
   实际 features、块大小、group/inode geometry。命令失败、默认特性不符或工具缺失
   均为测试环境失败并置红，不得 skip。
2. **黄金清单**：host 与 guest 输出统一结构字段（类型、规范化路径、mode、uid/gid、
   size、链接目标等），在 `LC_ALL=C` 下按稳定字段排序，并记录每个文件内容的
   SHA-256；比较规范化清单与哈希，不要求 debugfs 人类可读输出原样相等。
3. **离线 e2fsck**：guest 报 PASS 前先 sync 并干净 unmount；host 仅在离线镜像运行
   `e2fsck -fn`，最终退出码必须严格为 0，不允许任何非零退出或错误类别豁免。
   结构检查之外，必须比较全量内容 SHA-256、目录/链接语义和成功/失败操作计数。
4. **crash 后闭环**：记录初始/注入后/replay 后镜像 SHA-256；重启必须使用刚崩溃的
   同一镜像完成 replay，再干净卸载，最后离线 `e2fsck -fn` 严格为 0。按已确认操作
   日志校验持久化内容；未确认操作只接受测试模型定义的结果，不能只看结构无错误。
5. **200 次有效 crash（M7 UP 完整活动）**：固定配置
   `CORE-UP-EXT4-CRASH`，执行 `make test-ext4-crash CONFIG_ID=CORE-UP-EXT4-CRASH`。
   manifest 在运行前冻结以下唯一主类别和 expected 计数，actual 必须逐类相等且总计 200；

   | 主注入类别 | expected | 必须留下的专项证据 |
   |---|---:|---|
   | `needs_recovery/nonempty-replay` | 40 | 真实恢复需求及已提交事务的非空 replay |
   | `revoke` | 30 | revoke 记录生效，旧块引用不被错误回放 |
   | `commit-before` | 20 | commit 记录持久化前的注入点 |
   | `commit-after` | 20 | commit 记录持久化后的注入点 |
   | `flush` | 20 | 真实 CACHE FLUSH 前后位置及完成/故障状态 |
   | `abort` | 20 | abort 路径及未提交事务不被误回放 |
   | `checkpoint` | 25 | checkpoint 前后序列与日志块状态 |
   | `journal-reuse-wrap` | 25 | 实际日志复用/wrap 及 sequence 证据 |

   每个样本只计入一个主类别，辅助标签可另记但不得重复计数。只在真实写事务/写 BIO
   的有效注入窗口停止 QEMU；所有类别（不只是第一类）均须证明 replay 前镜像真实设置
   `needs_recovery`，且 replay 的已提交事务/块计数非零；
   空 replay、无效注入或缺类别证据均不计数并重做。八类每轮都执行第 4 项的同镜像重启
   replay、语义校验、干净卸载和严格离线 e2fsck 闭环。
   每轮从独立初始镜像开始，记录 config_id、完整命令、seed、QEMU cache 模式、主类别、
   注入阶段、已确认操作序列/计数、expected/actual 与各镜像 hash；禁止循环复用已崩溃
   镜像或换新镜像绕过 replay。
6. **M8 SMP crash 专项**：`CORE-SMP{1,2,4}-EXT4-CRASH` 各自运行 40 所冻结的
   非空 manifest，逐 config/类别记录 expected/actual 和独立 evidence，并执行同一闭环；
   这些轮次不并入或折抵 M7 的 UP 200 轮，最终 Core 必须同时取得两类证据。
7. **兼容矩阵**：显式 `-O` 覆盖 bs=1024/2048/4096、`^has_journal/has_journal`、
   64bit/flex_bg、dir_index 的阶段接受/拒绝组合；`noload` 只作为独立挂载选项测试，
   绝不出现在 mke2fs feature 组合中。
8. **大文件与高位物理块分离**：>4GiB 文件执行 RO/RW、截断与 sha256 校验，覆盖
   i_size_hi、64 位 i_size、i_blocks/huge_file；另用合成 extent/受控镜像覆盖
   `ee_start_hi != 0`。4KiB 块下物理块号 2^32 对应约 16TiB 的物理字节位置，
   该寻址测试不能用“文件长度 >4GiB”替代。
9. **目录压力**：大目录覆盖真实 htree split；若走重建路径，验证 INDEX_FL/dx 元数据
   已清除且内容不丢。不支持时验证错误返回与目录/操作计数完全不变。

## 6. 代码组织（对齐 Linux fs/ext4）

```text
fs/ext4/{mod,super,inode,extents,dir,namei,alloc,ioctl}.rs
fs/ext4/journal/{mod,journal,transaction,replay}.rs
```

每文件 ≤400 行；特性矩阵、extent/htree 纯函数与 bh IO 解耦，host cargo test 可直接
覆盖非法字段、深度上限、64 位高位和 split/rebuild，再以 qemu/e2fsprogs 做集成终验。
