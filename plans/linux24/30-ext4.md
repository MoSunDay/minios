# 30 — ext4 文件系统实现计划（四阶段）

> 目标：在 minios 上支持 ext4（磁盘格式兼容 e2fsprogs：host `mke2fs -t ext4` 生成、
> `debugfs/e2fsck` 校验）。参照内核 fs/ext4 + jbd2 的模块边界，规模按教学内核裁剪。

## 0. 磁盘格式速查（实现依据，对齐 e2fsprogs 语义）

- Superblock：字节偏移 1024，magic 0xEF53；关键字段：s_inodes_count/blocks_count/
  free_*、s_first_data_block、s_blocks_per_group、s_inodes_per_group、s_inode_size(256)、
  s_desc_size(64 若 64bit)、s_log_block_size（块=1024<<n）、s_feature_{compat,ro_compat,incompat}、
  s_journal_inum=8、s_desc_size、s_checksum_type。
- Group Descriptor（64B）：bg_block_bitmap_csum_{lo,hi}/bg_inode_bitmap_*/bg_inode_table_*/、
  bg_free_blocks_count_{lo,hi}/bg_free_inodes_count/bg_used_dirs_count、bg_flags、
  bg_itable_unused、bg_checksum（若 metadata_csum，P1 RO 需校验，否则忽略）。
- Inode：i_mode/i_uid/i_size_lo/i_atime/i_ctime/i_mtime/i_dtime/i_gid/i_links_count/
  i_blocks_lo/i_flags(i_blocks 高位 i_osd2)、i_block[15]（extent 根或直接块）、
  i_generation、i_extra_isize、i_checksum_lo。
- Extent 树：i_block 为 ext4_extent_header{magic 0xF30A, entries, max, depth, generation}；
  节点 ext4_extent_idx{leaf_lo/hi, unused} 或 ext4_extent{ee_block, ee_len(高bit=unwritten),
  ee_start_hi, ee_start_lo}；物理连续大段，4 层深度上限。
- 目录：dirent{inode, rec_len, name_len, file_type}；htree 目录：第一个块为 dx_root
  （dot/dotdot + dx_entry 计数/哈希伪装 dirent），节点块 dx_node；哈希 = half_md4（裁剪版）或 tea。
- journal（jbd2）：inode 8 指向日志区；j_header{j_magic 0xC03b3998, blocktype}；
  描述块（句柄标签）+ 数据/元数据块 + 提交块（+seq）；特性位 JBD2_FEATURE_*。

## 1. 阶段 P1 — 只读（M5）

范围：挂载 ro；块 1k/2k/4k；extent 读；目录线性+htree 读；filetype；symlink（快/慢）；
普通/目录/stat；lseek+getdents；符号链接与 readlink；fsstat。
明确不支持（挂载时检查并拒绝相应 feature_incompat 位）：inline_data、bigalloc、
encrypt、verity、metadata_csum（RO 需位图校验，延到 P4）、casefold。
- super.c：挂载/卸载、特性位矩阵校验、组描述符加载（全量驻留）、statfs。
- inode.c：按 (group, index) 定位 inode 表块；读 i_flags/extent 根；bmap(block→物理)；
  truncate 无（ro）；i_atime 不回写。
- extents.c：`ext4_ext_walk(path, logical)` 二分查找 → 下一层 bh；unwritten 段返回洞语义
  （读零）；洞（无 extent 覆盖）读零。
- namei.c/dir.c：线性扫描与 dx_root 解析（hash 计算→单节点内二分；实现 leaf 块线性回退）；
  "." ".." 处理；rec_len 越界容错（跳到下一块）。
- 测试：见 §5 e2fsck 闭环与黄金清单 diff。

## 2. 阶段 P2 — 读写（无日志）（M6）

- alloc.c：组选择（先本组→哈希目录（used_dirs 计数）→全局最优）；
  块分配：组内 first-fit 位图 →（收紧为 buddy-per-group 可选）；预分配（目标 8 块窗口）；
  inode 分配与目录项徽章（bg_used_dirs_count）；配额 Out。
- extents.c 写：尾部追加；ee_len 装不下→新 extent；路径上的 idx 分裂（B+ 树插入，
  深度自增上限 4）；unwritten = fallocate 语义（Stretch）。
- dir.c 写：尾部 rec_len 收缩插入；块满→新块；线性目录超阈值(1 块)→ 转 htree
  （dx_root 构建 + hash 重排，一次性迁移，简化实现）；htree 分裂（P2 后期，
  允许先退化：标记 dir 不再建索引只增长线性块 —— 但 e2fsck 必须接受）。
- inode.c 写：i_size/i_blocks/i_ctime/mtime 维护；unlink/rmdir 的 i_dtime；
  link 计数；rename（同目录/跨目录：目录项移动+ .. 更新，采用 e2fsck 允许的顺序）。
- 位图/统计回写：分配即置位并更新 group desc + super 计数（NO journal 时挂载选项
  `noload` 语义：存在 journal inode 则 P2 模式要求 `-o noload` 或镜像以
  `mke2fs -O ^has_journal` 生成）。
- 溢出位：>2^32 块不做（32 位块号内部）；64bit feature RO 兼容（hi 位拼接读，写时断言不越界）。

## 3. 阶段 P3 — jbd2-lite 日志（M7）

- journal/：事务模型（handle → transaction{tid, buffers, state}）；
  提交流程：描述块（tag 数组）→ 元数据 bh 原地写（ordered：数据先于日志提交落盘）→
  提交块（seq）→ checkpoint（释放日志块，环形复用）。
- 挂载：读超级块 j_sequence/j_start → 回放（blocktype 分发：descriptor/commit/abort/revoke）；
  revoke 语义（防旧引用回放）。
- 集成点：ext4 元数据修改必须 `ext4_journal_start/stop` 包裹（P2 完成后插桩）；
  bdflush/kupdated 与 checkpoint 协作；fsync = 数据落盘 + 事务提交等待。
- 只实现 ordered 数据模式；writeback 模式 Stretch；journal_checksum Stretch。
- 崩溃一致性：见 §5。

## 4. 阶段 P4 — 高级特性（按余力）

- metadata_csum（RO 校验位图/GD/inode/目录块 → 写路径更新校验和）；
  flex_bg（读支持 P1 已含，写支持）；mballoc-lite（局部性组内伙伴，替代 P2 first-fit）；
  nojournal 模式常驻；dir_index 关闭回退；xattr（RO，user.* 只读）Stretch；
  inline_data RO Stretch；extent unwritten(fallocate) Stretch。
- 明确不做：bigalloc、encryption、verity、casefold、project quota、mmp。

## 5. 测试闭环（与 40-testing-ci.md 联动）

1. 黄金清单：host 侧 `debugfs -R 'ls -l -p -R /'` 导出全树清单；内核侧遍历镜像产出
   同格式清单；diff 必须为空（P1 gate）。内容校验：对每文件 sha1（debugfs dump vs cat）抽样。
2. e2fsck 闭环（P2/P3 gate）：脚本生成负载（建/删/追加/截断/重命名/嵌套目录/多组满压），
   每轮 `e2fsck -fn` 必须零错误（或仅 metadata_csum 缺失类的已知项）。
3. 崩溃注入（P3 gate）：qemu 运行负载中随机 kill（脚本循环），重启挂载回放，
   e2fsck -fn 判定；≥200 次统计报告。
4. 兼容矩阵：mke2fs 参数 {bs=1024,2048,4096}×{has_journal,noload}×{64bit,flex_bg}
   ×{dir_index} 组合冒烟。
5. 大文件：>4GB 单文件（块 4k，ee_start_hi 路径）RO/写；目录 10 万项（htree 深度 1）。

## 6. 代码组织（对齐 linux fs/ext4）

```
fs/ext4/{mod,super,inode,extents,dir,namei,alloc,ioctl(空)}.rs
fs/ext4/journal/{mod,journal,transaction,replay}.rs
```
每文件 ≤400 行；extent 树与哈希计算、位图扫描等纯函数与 bh IO 解耦 → host cargo test。
